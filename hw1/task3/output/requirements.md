# 需求模型：校园自习室智能预约系统（requirements.md）

> 来源标记约定：
> - **[输入支持]**：可从 `baseline.md` 原文直接读出，附原文引用。
> - **[推断假设]**：为完成建模暂时作出的推断，附推断理由与验证对象。
> - **[新增提案]**：原始输入没有要求的功能或政策，附预期价值与代价。
>
> 凡涉及具体数值或政策（预约时长、签到宽限期、信用扣分、候补排序等），本文一律不写成确定事实，而是标为推断假设并登记到 `assumptions.md` 的待确认问题。

## 一、业务目标

| 编号 | 目标 | 来源类别 |
| --- | --- | --- |
| G1 | 为学生提供自习室的在线预约能力，减少现场抢占与无序占座 | **[推断假设]**：原文只有「预约系统」，未说明痛点；推断校园场景的核心痛点是无序占座。验证对象：学生与自习室管理员。 |
| G2 | 提高自习室座位/房间的使用效率与利用率 | **[推断假设]**：预约系统通常以提升资源利用率为目标。验证对象：学校信息化部门与物业。 |
| G3 | 用「智能」手段降低用户选择成本与冲突（如推荐、自动匹配、冲突消解） | **[推断假设]**：原文含「智能」，但未定义含义；此处给出可验证的最小解释。验证对象：校方产品负责人。 |
| G4 | 让管理员可维护自习室资源并处理违规与异常 | **[新增提案]**：原文未提管理端；但无管理能力则资源无法维护。价值：保障系统可运营；代价：增加管理与权限模块工作量。 |

## 二、系统范围

### 2.1 范围内（候选）

- 预约的创建、查询、取消、签到、签退。**[推断假设]**（原文只支持「预约」这一核心词）
- 用户身份与权限。**[推断假设]**
- 自习室资源与座位/房间配置。**[推断假设]**
- 「智能」辅助能力（推荐或冲突消解）。**[推断假设]**
- 管理端维护与报表。**[新增提案]**

### 2.2 范围外（暂不纳入）

- 支付、计费等商业功能。**[新增提案]**：原文面向校园公共资源，默认免费。
- 自习室外其他设施（如教室排课、会议室）的统一预约。**[推断假设]**：避免范围蔓延，验证对象：学校信息化部门。

## 三、关键业务规则

> 编号规则：BR-n。每条都标注来源类别。凡数值型规则均不写死。

| 编号 | 规则 | 来源类别与说明 |
| --- | --- | --- |
| BR-1 | 用户必须先通过校园身份认证才能预约 | **[推断假设]**：原文面向校园；预约需绑定真实身份。验证对象：学校信息化部门（是否有统一身份认证）。 |
| BR-2 | 预约针对具体自习室的可用资源在指定时间段内独占 | **[推断假设]**：原文仅说「预约」；独占是预约语义的必要推断。验证对象：管理员。 |
| BR-3 | 同一用户不得对**同一资源**的**时间重叠**时段创建多条有效预约 | **[推断假设]**：防止同一资源被同一人重复占用；已按校验 P3 收窄为「同一资源」，以消除与场景的矛盾。「同一用户是否可在同一时段预约**不同资源**」属政策选择，见 Q12，不写死。验证对象：业务方。 |
| BR-4 | 用户可在规则允许的时间内取消预约 | **[推断假设]**：无取消能力则预约不可用。允许的时间窗为待确认问题 Q4。 |
| BR-5 | 用户应在开始使用前完成签到（check-in），否则可能被视为违约 | **[推断假设]**：原文未提签到；这是防止占座的常见机制。签到方式与宽限期见 Q5、Q6。 |
| BR-6 | 用户使用结束后应签退（check-out）以释放资源 | **[推断假设]**：便于回收资源与统计。验证对象：管理员。 |
| BR-7 | 系统对违约（爽约/超时占用等）可能采取信用或限制措施 | **[推断假设]**：原文未提信用；仅作为候选政策，具体扣分与恢复规则见 Q7，不写死数值。 |
| BR-8 | 满员时可进入候补队列，出现空位后按规则通知或分配 | **[推断假设]**：原文未提候补；是提升利用率与公平性的候选能力。排序策略见 Q8，不写死。 |
| BR-9 | 「智能」能力表现为向用户推荐可用资源或消解预约冲突 | **[推断假设]**：对原文「智能」的最小可验证解释；具体范围见 Q9。 |
| BR-10 | 管理员可创建、修改、停用自习室及其资源 | **[新增提案]**：价值是可运营；代价是额外管理界面与权限设计。 |
| BR-11 | 管理员可处理申诉、解封、查看统计报表 | **[新增提案]**：价值是可治理；代价是报表与流程开发。 |
| BR-12 | 用户只能查看与操作自己的预约，管理员按权限查看全部 | **[推断假设]**：基于最小权限原则的访问控制推断。验证对象：信息安全/合规方。 |
| BR-13 | 预约数据应按校方隐私政策保存与使用 | **[新增提案]**：价值是合规；代价是需接入合规审查与数据保留策略。具体保留期限见 Q10。 |

| --- | --- | --- |
