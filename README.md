# 高级软件工程

UCAS软件工程研究生一年级课程

## 课程介绍

课程面向 **AI 原生软件系统**，围绕三个问题展开：发现有价值的需求，设计可靠且可演化的系统，以及验证质量并持续改进。内容从需求工程、架构、测试、DevOps，延伸到智能体架构与智能运维。学习以课堂讲授和项目实践结合；考核包括期末考试、平时作业与课堂参与、项目实践。

## 第一讲：软件工程的代际演进

| 阶段 | 要解决的问题 | 代表方法 | 新的瓶颈 |
| --- | --- | --- | --- |
| **1.0 工程化** | 大型软件开发失控 | 瀑布模型、结构化方法、面向对象、CMM/CMMI | 需求难以预先冻结，反馈较晚 |
| **2.0 服务化** | 需求变化快、交付周期长 | 敏捷迭代、Scrum、DevOps、微服务、云原生 | 理解、测试和运维仍高度依赖人的脑力 |
| **3.0 智能化** | 软件生产中的智力劳动成为瓶颈 | 大模型与智能体驱动的 Agentic Loop | 正确性、安全、上下文规模及责任划分尚待解决 |

3.0 的核心闭环是 **需求理解 → 设计生成 → 代码生成 → 测试检验 → 根据结果修正**。智能体可以执行更多步骤，但工程师仍需定义目标、验收标准并把关质量。三代方法是在不同条件下作出的取舍，并非后一代完全取代前一代。

## 第二讲：需求工程专题（一）

**需求工程**回答系统“做什么、为什么做”，主要经过需求获取、分析、规格说明、验证和持续管理。需求可分为业务需求、用户需求、功能需求与非功能需求；后者包括性能、安全、可靠性、易用性等质量约束。访谈时还要发现用户未主动说出的隐式需求。

传统方法通常以瀑布流程和 **软件需求规格说明书（SRS）** 明确需求，适合需求较稳定、需要严格评审的场景，但变更成本高。敏捷方法则通过短周期交付和持续反馈调整需求，常用以下实践：

- **用户故事**：按“作为〔角色〕，我想要〔目标〕，以便〔价值〕”表达需求；用 **INVEST** 检查其独立、可协商、有价值、可估算、足够小、可测试。
- **BDD 与 Gherkin**：用 **Given（前提）—When（行为）—Then（预期结果）** 描述可验收的场景，同时覆盖正常流程与异常、边界情况。场景可连接 Cucumber 等工具，成为持续更新的需求说明与自动化验收测试。
- **低保真界面草图和故事板**：将文字场景可视化，及早发现交互或需求遗漏，再反过来修正场景。

课件以 **校园自习室预约系统** 贯穿示例：从提升座位利用率的业务目标，细化到学生预约、管理员管理教室、超时释放座位等故事，并为预约冲突、未登录、并发与超时等情况定义验收结果。课后作业要求完成需求分层、故事拆分、至少 8 条附验收准则的用户故事，以及 3 个 Gherkin 场景。
